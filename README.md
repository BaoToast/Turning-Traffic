# Turning Traffic 路口尖峰轉向交通量分析系統

瀏覽器式交通量資料管理與分析工具，針對每季多路口交通量調查的實務流程設計。資料預設保存在使用者瀏覽器，可用 JSON／ZIP 備份，不會自動上傳原始調查檔。

## 主要功能

- 批次讀取 `.xls`、`.xlsx`、`.xlsm`，辨識交通量、監測日誌、時相圖並略過照片。
- 以**連續 60 分鐘**計算 AM／PM 尖峰。格距不限 15 分鐘：**15、20、30、60 分鐘都支援**
  （條件是格距要能整除 60，所以 45 分鐘或 2 小時一格算不出來，會明確回報「資料不足」
  而不是給一個其實不是一小時的數字）。搜尋範圍、格距判定與同值決策集中在 `lib/traffic.ts`。
- 車種組成可切換全調查時段、AM 尖峰與 PM 尖峰；全程使用實際輛數，不以 PCU 代替車輛數。匯入器會依欄名辨識任意數量車種，新車種可獨立分析或併入四個標準類別。
- 缺值、總數、尖峰時段與車種合計檢查；不把實際調查到的高流量誤列為異常。
- 車種合計只比較同方向、同時段且同為實際車輛數（輛/hr）的欄位；PCU/hr 與輛/hr 不直接比較。
- T 字、四叉、五叉、六叉、七叉、八叉 SVG 轉向圖（手動新增支線上限 `MANUAL_ARM_LIMIT = 8`，v2.1.80 起）；⚠️ 這一行原本只寫到七叉，從 v2.1.80 放寬上限那一版起就漏了「八叉」（2026-09-25 補）。各支線分別顯示「由該支線進入中央路口」與「離開中央路口後駛入該支線」兩種合計及單位。
- 每個分析車種皆有可人工維護的左／直／右當量係數；新車種預設 1.0，需由使用者依計畫依據確認。每次匯入保存車種歸類與係數快照，報表與備份均可追溯。
- 道路管理只保留支線名稱、原始 A～G 代碼、方位、角度與實際起訖流向；不要求與尖峰流量無關的車道容量資料。
- 支線方位由角度自動產生且不可人工修改：0° 為東、90° 為南、180° 為西、270°／-90° 為北，中間角度依八方位換算。
- 多計畫分開管理，可把同一季度的不同計畫路口放入同表比較；分析頁先選季度再選標準路口，T14／T15 等站號只供追溯。
- 歷季趨勢依標準路口名稱合併跨季站號，以起始與結束季度選擇任意長度範圍，圖表與匯出圖片會保留全部季度。
- PNG、SVG、PDF 與整季圖面批次輸出，另支援舊版 `.xls` 資料表。
- Excel 報表**共 10 個可選工作表**（匯出中心逐項勾選，不是固定三類）。
  清單的唯一來源是 `lib/final-features.ts` 的 `REPORT_ITEMS`：
  各路口駛出尖峰流量、各路口駛入尖峰流量、駛入駛出各路口流量、車種組成分析、
  歷季趨勢比較、各路口支線尖峰流量、OD轉向矩陣、支線流量平衡、
  資料品質檢核、車種轉向當量。
  歷季趨勢附**原生可編輯折線圖**（不是圖片，在 Excel 裡改數字圖會跟著動）。
  ⚠️ 「原始儲存格追溯」**不在這 10 個裡**——它是「流量核對工作台」另一支
  匯出（另存成 `…_流量核對.xlsx`）。2026-09-23 的複查抓到這一列把它算進來、
  又把「駛出／駛入」兩張併成一個「尖峰流量」，總數剛好也是 10，所以
  數字對、清單錯。
- JSON／ZIP 備份還原、A／B 電腦移轉、同季度同站號覆蓋策略、錯誤季度刪除、名稱映射與版本紀錄。
- 最終版新增儲存格級來源追溯、匯入版本差異／還原、成果審核狀態、季度品質報告，以及 OD 矩陣、支線平衡與連續 60 分鐘尖峰敏感度分析。
- 道路與流向管理保留清楚的簡潔道路預覽；需要調整轉向圖數據框時，另開全幅「圖卡排版預覽」，可直接拖曳或輸入左右 X／上下 Y 位移。版面依標準路口跨季度共用，匯出前會提示可能重疊。
- 網站內建給非交通專業使用者的「新手操作手冊」頁面，並提供完整 **PDF** 版下載；
  內容涵蓋完整操作流程、名詞、單位、品質檢查、轉向圖、輸出與備份。
  ⚠️ **自 v2.1.64 起只出 PDF**（使用者指定，三支同步）；Word 版的產生器與檔案
  都已移除，`tests/manual-copies-identical.test.mjs` 有一條反面守門擋它回來。
  這一行原本還寫著「PDF／DOCX」，而包裡根本沒有 .docx，點下去會 404。
- 系統不加入容量相關分析，專注尖峰轉向流量彙整與比較。

## 尖峰計算原則

1. 將資料正規化成時間間隔列；預設為 15 分鐘。
2. 僅接受時間連續、**累計到剛好 60 分鐘**的那幾列。
   ⚠️ **v2.1.83 起不再以「列數」組成視窗**：每一格用**它自己的長度**
   （匯入時從時間欄原始文字的起訖存下來，讀不到才退回整份檔案的眾數），
   逐格累加到剛好 60 分鐘；相鄰判準是「這一格的起點必須等於上一格起點＋
   上一格自己的長度」，所以跨不過空隙。`needed = 60 / intervalMinutes`
   現在只留作「格長能不能整除 60」的前置檢查。
   ⚠️ 這一段原本描述的是被 v2.1.83 取代掉的機制（固定列數：15 分鐘 4 列、
   20 分鐘 3 列…），那個寫法在格長混用時會把 `50+50+50+100 = 250`
   當成一小時的量（2026-09-25 改寫）。
3. AM 預設搜尋 00:00–12:00，PM 預設搜尋 12:00–24:00。
4. 以所有已辨識流量欄位總和挑選最大視窗；同值取較早視窗。
5. 對中選視窗分別加總各流向、左直右與車種；參考計算檔只用於差異驗證。

## 本機執行

需要 Node.js 22 與 npm。

```bash
npm ci
npm run dev
```

SheetJS 官方 0.20.3 發布包已收進 `vendor/` 並以 SHA-256 鎖定；
`npm ci` 不再依賴 `cdn.sheetjs.com`，受限網路或離線環境也可重現建置。
詳見 `DEPLOYMENT.md`。

正式檢查：

```bash
npm run build
npm test
npm run test:engine
npm run build:github
```

## GitHub Pages

GitHub 專案 Settings → Pages 的 Source 固定為 **Deploy from a branch → main → / (root)**。推送 `main` 後，內建的 `pages-build-deployment` 會發布根目錄網站；`.github/workflows/pages.yml` 只負責執行建置與測試，不另行部署。

若用 GitHub 網頁手動上傳，請特別確認 `.github/`、`.nojekyll`、`.gitignore` 等點號開頭項目已一併上傳。判斷線上是否為最新版時，只使用帶版號的手冊檔名、`?v=` 查詢參數或該版專屬的雜湊資產；不要只讀固定檔名判斷，以免被 CDN 快取誤導。

## 資料與隱私

匯入 Excel 後只把正規化結果存到瀏覽器本機儲存空間；原始檔案本身不會被網站保存。更換瀏覽器或清除網站資料前，請先下載 ZIP 備份。

## 實檔驗證狀態

已以使用者提供的 115Q2 T15-01～05 實際 `.xlsx` 驗證。辨識結果為：T15-01 七個入口、168 個 OD×車種欄位；T15-02 三個入口、36 個左直右×車種欄位；T15-03～05 各四個入口、48 欄。五檔均讀到 16 個 15 分鐘區間與調查日 2026-05-04。另以 BIFF8 記憶體轉檔回歸測試 `.xls` 相容讀取。
