# Turning Traffic 路口尖峰轉向交通量分析系統

瀏覽器式交通量資料管理與分析工具，針對每季多路口交通量調查的實務流程設計。資料預設保存在使用者瀏覽器，可用 JSON／ZIP 備份，不會自動上傳原始調查檔。

## 主要功能

- 批次讀取 `.xls`、`.xlsx`、`.xlsm`，辨識交通量、監測日誌、時相圖並略過照片。
- 以連續 4 個 15 分鐘區間計算 60 分鐘 AM／PM 尖峰；搜尋範圍、區間長度與同值決策集中在 `lib/traffic.ts`，可調整與測試。
- 車種組成、方向比例、尖峰方向、多路口與 2–4 季比較。
- V/C 只在車道數、飽和流率、有效綠燈與週期齊全時顯示；不足時列出缺少項目。
- 規則式＋統計離群的異常流量提醒，以及缺值、總數、尖峰時段、車種合計檢查。
- 車種合計只比較同方向、同時段且同為實際車輛數（輛/hr）的欄位；PCU/hr 與輛/hr 不直接比較。
- T 字、四叉、五叉、六叉、七叉 SVG 轉向圖；正式版以跨路口箭線顯示實際去向，另有單一方向聚焦模式。
- 四車種左／直／右當量表可人工維護；附來源說明、飽和流率初篩範圍與號誌容量換算工具。
- 多計畫分開管理及跨計畫比較；正式網站空白起始，不預載範例數值。
- PNG、SVG、PDF、可編輯 `.xlsx`、舊版 `.xls` 與整季批次輸出。
- JSON／ZIP 備份還原、A／B 電腦移轉、同季度同站號覆蓋策略、錯誤季度刪除、名稱映射與版本紀錄。
- 本系統不提供 LOS／HCM 分析。

## 尖峰計算原則

1. 將資料正規化成時間間隔列；預設為 15 分鐘。
2. 僅接受時間連續的 4 列，形成完整 60 分鐘滑動視窗。
3. AM 預設搜尋 05:00–12:00，PM 預設搜尋 12:00–23:00。
4. 以所有已辨識流量欄位總和挑選最大視窗；同值取較早視窗。
5. 對中選視窗分別加總各流向、左直右與車種；參考計算檔只用於差異驗證。

## 本機執行

需要 Node.js 22 與 pnpm。

```bash
pnpm install
pnpm dev
```

正式檢查：

```bash
pnpm build
pnpm test
pnpm test:engine
pnpm build:github
```

## GitHub Pages

推送 `main` 後，`.github/workflows/pages.yml` 會建立靜態版並發布。首次使用時需在 GitHub 專案 Settings → Pages 將 Source 設為 **GitHub Actions**。

## 資料與隱私

匯入 Excel 後只把正規化結果存到瀏覽器本機儲存空間；原始檔案本身不會被網站保存。更換瀏覽器或清除網站資料前，請先下載 ZIP 備份。

## 實檔驗證狀態

已以使用者提供的 115Q2 T15-01～05 實際 `.xlsx` 驗證。辨識結果為：T15-01 七個入口、168 個 OD×車種欄位；T15-02 三個入口、36 個左直右×車種欄位；T15-03～05 各四個入口、48 欄。五檔均讀到 16 個 15 分鐘區間與調查日 2026-05-04。另以 BIFF8 記憶體轉檔回歸測試 `.xls` 相容讀取。
