■ v2.1.25：佔比拆成兩個方向

  使用者問：「駛入 422.4／駛出 417.8／佔駛入 10.6% —— 這個 10.6%
  是方向無關的值，還是只是駛入的？」

  是駛入的，而且**舊版永遠只寫得出駛入那一組**。兩個百分比其實都算了，
  但輸出是「if (inShare) … else if (outShare) …」，只有整筆完全沒有駛入
  資料時才輪得到駛出；而 inflowPcu 由 destinationFlowTotal() 產生、
  那支函式永遠回傳數字，所以「佔駛出」是**執行不到的死碼**，
  一次都沒有被寫出來過。選項名稱又只寫「佔路口總量百分比」，
  沒說是哪個方向，標籤還會隨資料在兩者之間悄悄變動。

  兩個方向的分母相同（都是路口總量，因為駛入合計必然等於駛出合計），
  但分子不同，數字差很多——實測某一筆：
    路口B 駛入 10.4%／駛出 27.6%
    路口F 駛入 42.8%／駛出 14.7%

  拆成「各支線佔駛入路口總量百分比」與「各支線佔駛出路口總量百分比」，
  各勾各的；兩個都勾時駛入排在駛出前面。

  **沒有動任何計算**：舊的 share 鍵只換成 shareIn，**不是**展開成兩項
  ——展開會讓既有範本多出一段從來沒有過的「佔駛出」，那就不是輸出不變了。
  已用整份字串比對的迴歸測試釘住。

  新增單元測試 5 項（含「兩個方向用同一個分母、各自加總都是 100%」的
  防線——日後有人把駛出的分母換掉，每一格看起來仍是合理的百分比，
  畫面上看不出來）與端對端檢查 3 項。

■ v2.1.24-1：範本現在專屬於各自的計畫

  結論草稿的「條件範本」與報表的「匯出項目範本」，舊版都存成一份
  扁平清單、所有計畫共用——在甲計畫存的範本，切到乙計畫照樣列出來。

  這不只是看了礙眼：結論條件裡存著 intersectionKeys 與 branchNames，
  那是該計畫專屬的識別字，套到別的計畫會篩出 0 筆而找不出原因。
  這支程式其實已經知道這件事（換計畫時本來就會重設「正在編的條件」
  與草稿，理由就寫在那段註解裡），漏掉的只有「已存起來的範本清單」。

  改法與 pceByProject／catalogByProject／mappingsByProject 完全一致，
  連 setter 都沿用同一個 scopedSetter。

  **既有範本不會不見**：升版時舊的扁平清單會分給每一個計畫各一份，
  請使用者到各計畫把用不到的刪掉一次，之後新存的就只屬於當下那個計畫。
  （全部歸給某一個計畫的話，其他計畫就再也找不到過去存的範本。）
  備份與還原同樣依計畫分開帶，舊版備份的扁平清單也讀得懂。

■ v2.1.24-2：「各支線各車種駛入／駛出車輛數」拆成兩個勾選項

  舊版一勾就是兩個方向都寫，只需要其中一個方向時只能產生完再自己刪。
  拆成「各支線各車種駛入車輛數」與「各支線各車種駛出車輛數」兩項。

  只勾一個方向時「呈現方式」那一區會收起來——「雙向合計」是把兩個
  方向加起來，對單一方向來說那是**錯的數字**（會把另一個方向的車也
  算進去），而且它一樣會印出一行看起來合理的文字，畫面上看不出來。

  **沒有動任何計算**：舊的 branchComposition 鍵在 normalizeCondition
  裡原地展開成新的兩項，既有範本與備份產生的草稿與 v2.1.23 逐字相同，
  已用「整份字串比對」的迴歸測試釘住（只比幾個 match 驗不出多寫或
  少寫一段）。

■ 新增測試

■ 上一版（v2.1.23）：結論草稿的「時段」可以兩個都不勾

  需求

  只想要某個路口「全調查時段」的車種組成那一行，但舊版強制
  「時段至少要留一個」——取消最後一個尖峰時會被自動加回去，
  草稿一定夾帶不要的尖峰段落，只能產生完再自己刪。

  兩個都不勾 ＝ 不敘述尖峰時段，只寫全調查時段的數值。
  這時記得在「要寫哪些數字」勾起「車種組成」。

  配套三件事：統計範圍那一行會寫明「不敘述尖峰時段」；
  沒有尖峰時不再印「PCU/hr 是該尖峰一小時的流率」那句說明；
  兩個都不勾卻只選了寫在尖峰底下的項目時，草稿會直接說明產生不出內容，
  而不是交出一份只有標題的空草稿。

  **沒有動任何計算**：有勾時段時的輸出與 v2.1.22 完全相同，已用測試釘住。

  另外修正一個相關的小陷阱：舊範本沒有 peaks 欄位時仍要補上預設的
  上午＋下午，但「有欄位、是空陣列」是使用者刻意的選擇，不可以被補回預設。
  這兩種情況以前被當成同一件事。


發布方式（重要，和以往不一樣）
-----------------------------------------------------------------

本包是原始碼修正包，不含建置後的網站。
根目錄的 index.html 與 assets/ 已刻意移除，必須由發布者自己重新建置。

原因：本版由 Claude 在一個連不到 cdn.sheetjs.com 的環境完成。
package.json 的 xlsx 指向 SheetJS 官方 0.20.3 發布包（安全警示的修正版），
該環境抓不到，所以在那裡產生的網站成品會把 SheetJS 悄悄降回舊版——
而且從畫面上完全看不出來。與其交一份可能有問題的成品，不如不交。

發布步驟：

  1. 把本包的檔案覆蓋到 repository（https://github.com/baotoast/Turning-Traffic）。
  2. npm ci          ← 需要連得到 cdn.sheetjs.com
  3. npm run lint    ← 應為 0 錯誤 0 警告
  4. npm test        ← 應為 160 項全過（模組 40 ＋ TypeScript 120）
  5. npm run e2e     ← 8 支瀏覽器測試全過
  6. npm run build:github，把產出的 index.html 與 assets/ 放回根目錄，
     手冊 PDF／DOCX 也會一併帶到根目錄
  7. commit + push

上傳只覆蓋同名檔案、不會刪除，所以一定要手動刪掉：
  ・Turning-Traffic-v2.1.26-新手操作手冊.pdf 與 .docx（根目錄與 public/）
  ・assets/ 底下 v2.1.26 的五個檔案：
      index-DhbGkujF.js、index-Jyo1WJCv.css、html2canvas-DHtv7W1-.js、
      index.es-DIeOVov2.js、purify.es-ChwZkWde.js
    新版的檔名雜湊不同，覆蓋不到它們。第 8 項檢查就是在擋這件事，
    沒刪乾淨的話 npm test 會直接紅字告訴你。

若用 GitHub 網頁手動上傳，點號開頭的項目會被靜默濾掉；
請另外確認 .github/workflows/pages.yml、.nojekyll、.gitignore 與
.openai/hosting.json 都還在（第 5 項檢查也會擋）。

部署完成後請確認：
